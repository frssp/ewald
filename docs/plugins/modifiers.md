# Modifier plugins

A modifier is a class with a constructor that stores its parameters and a
`modify(data, ctx)` method. The built-in modifiers in `src/ewald/modifiers/` are written this
way, and so is the complete example in
[`examples/plugins/local_composition.py`](https://github.com/frssp/ewald/blob/main/examples/plugins/local_composition.py),
which this page walks through.

Put the file in the plugin folder and decorate the class with `@modifier`, or publish it as an
`ewald.modifiers` entry point, and ewald finds it like a built-in modifier: in the GUI menu, in
the Claude tools and as `from ewald.modifiers import LocalComposition`.

## A modifier class

```python
import numpy as np
from ewald import Modifier
from ewald.neighbors import find_pairs


class LocalComposition(Modifier):
    """Fraction of neighbors within ``cutoff`` that are ``element``."""

    def __init__(self, cutoff: float = 3.0, element: str = "Cu"):
        self.cutoff = cutoff
        self.element = element

    def modify(self, data, ctx):
        xp, be = ctx.xp, ctx.backend
        i, j, _delta, _dist = find_pairs(data.positions, data.cell, self.cutoff, backend=be)
        is_element = xp.asarray(data.types == self.element, dtype=xp.float64)
        total = xp.bincount(i, minlength=data.count).astype(xp.float64)
        same = xp.bincount(i, weights=is_element[j], minlength=data.count)
        fraction = be.to_numpy(xp.where(total > 0, same / xp.maximum(total, 1), 0.0))
        data[f"Local {self.element} Fraction"] = fraction
        data.attributes["LocalComposition.mean"] = float(np.mean(fraction))
```

```python
pipe.modifiers.append(LocalComposition(cutoff=3.0, element="Cu"))
data = pipe.compute(0, device="cuda")
```

## The contract

**Constructor.** Store every argument as an attribute of the same name, and give every
argument a default if you can. `Modifier.parameters()` reads the constructor signature and
these attributes; the GUI parameter form, `repr(modifier)`, the cache keys of trajectory
modifiers, and the scripts generated by the Render workspace and the Claude tools are all built
from it. A modifier whose constructor needs no arguments can be added from menus without a
dialog.

**`modify(data, ctx)`.** `data` is a shallow copy of the frame: you may add, replace or remove
entries of `data.particles`, `data.attributes` and `data.tables`, but **never write into an
existing array**, because it is shared with cached frames. Return `None` to keep `data`, or
return a new `DataCollection` (for example `data.delete(mask)`) when the particle count
changes.

**The context `ctx`.**

| Member | Use |
|---|---|
| `ctx.frame` | the frame being computed |
| `ctx.xp`, `ctx.backend` | the array module (NumPy or CuPy) and its backend; `backend.to_numpy(a)` converts results |
| `ctx.source_frame(k)` | the unmodified input of frame `k`, e.g. a reference configuration |
| `ctx.input_frame(k)` | frame `k` as it reaches this modifier, with every modifier above it applied |
| `ctx.upstream_key()` | a hashable fingerprint of everything above this modifier, for caching |
| `ctx.pipeline` | the pipeline, e.g. `ctx.pipeline.num_frames` |

**Errors.** Raise an exception with a message a user can act on (`ValueError("cutoff must be
below half the cell width")`). The pipeline stores it in `modifier.status`, the GUI shows it on
the modifier's row and keeps the rest of the pipeline running.

## Outputs other code understands

- Per-particle results are properties with OVITO-style names in title case with spaces:
  `"Local Cu Fraction"`, `"Structure Type"`. Expressions then see them without spaces
  (`LocalCuFraction > 0.5`) and the inspector, `ColorCoding` and exporters pick them up.
- Global results are attributes prefixed with the modifier name: `"LocalComposition.mean"`.
- Curves and histograms are tables: `data.tables["local-composition"] = {"x": x, "count": n}`,
  a dict of equal-length columns. The GUI's Plots tab plots any table, and `TimeAveraging`
  can average it over frames (`TimeAveraging("table:local-composition")`).
- Colors are a `"Color"` property of shape N×3 with values in 0..1. If your modifier
  classifies particles, offer `color_by_type: bool = True` as the structure analyses do.
- If the analysis can be limited to a subset, offer `only_selected: bool = False` and use
  `data.selection`.

## Running on the GPU

Write array code against `ctx.xp` and pass `backend=ctx.backend` to ewald's kernels
(`ewald.neighbors.find_pairs`, `ewald.kernels.rdf`, `msd_fft`, `connected_components`, ...), and
the same modifier runs with NumPy and with CuPy. Convert to NumPy with `ctx.backend.to_numpy`
only when storing a result in `data`. Tests run the NumPy path, which exercises the same code.
Use numba or a C extension only for a measured hot spot, and keep a NumPy path next to it.

## Modifiers that read the whole trajectory

A modifier that needs other frames (MSD, time averages, paths) reads them with
`ctx.input_frame(k)` one at a time, so lazy readers stay lazy, and caches its result under
`(ctx.upstream_key(), repr(self))` so that it is computed once and recomputed only when a
parameter, an upstream modifier or the source changes:

```python
class MeanHeight(Modifier):
    """Mean z of all particles over frames ``start:stop``."""

    def __init__(self, start: int = 0, stop: int | None = None):
        self.start = start
        self.stop = stop

    def modify(self, data, ctx):
        key = (ctx.upstream_key(), repr(self))
        if getattr(self, "_key", None) != key:
            stop = ctx.pipeline.num_frames if self.stop is None else self.stop
            z = [ctx.input_frame(k).positions[:, 2].mean() for k in range(self.start, stop)]
            self._key, self._table = key, {"Frame": np.arange(self.start, stop), "Mean Z": np.array(z)}
        data.tables["mean-height"] = self._table
```

`src/ewald/modifiers/trajectory.py` has the full pattern, including selections and particle
matching by id.

## Functions instead of classes

For a one-off analysis, a function `f(frame, data)` or `f(frame, data, ctx)` appended to
`pipe.modifiers` is a modifier. `PythonModifier(f, threshold=2.5)` passes extra keyword
parameters. In the GUI, the Python script modifier keeps the function's code with the pipeline.
Write a class when the analysis has parameters you want in the GUI form, or when you want to
share it.

## Registering it

```python
from ewald.plugins import modifier


@modifier(category="Analysis")          # bare @modifier puts it under "Plugins"
class LocalComposition(Modifier):
    ...
```

In a file in the plugin folder (`ewald plugins` prints where it is), or in an installed package
with an entry point (see [Packaging and sharing](packaging.md)), this registers the class once
per process. `ewald.plugins.register_modifier(cls, name=None, category="Plugins")` does the same
from a script or the GUI console. A plugin cannot use the name of a built-in modifier; that
raises `ValueError`, and `ewald plugins` reports the file as failed.

A registered modifier

- imports like a built-in: `from ewald.modifiers import LocalComposition`, so the scripts that
  the Render workspace and the Claude tools generate run unchanged on any installation that
  has the plugin;
- appears in the GUI under Add modification › *category*, in the Pipeline menu and in the
  command palette, if it constructs with no arguments. Its parameter form is generated from the
  constructor: a checkbox for `bool`, spin boxes for `int` and `float`, a text field for `str`,
  and a Python-literal field for tuples, lists and `None`;
- is listed by `ewald plugins`.

For a menu entry with specific arguments, add it yourself:
`ewald.gui.pipeline_panel.register_modifier("Analysis", "Local Cu", lambda: LocalComposition(3.0, "Cu"))`.

## Claude tools and `llms.txt`

The Claude tools (`list_modifiers`, `add_modifier`) offer registered plugin modifiers next to
the built-in ones, with the signature and the first paragraph of the class docstring, so write
that paragraph as a one-sentence description. `llms.txt` stays core-only by design, so the same
file is valid on every installation; `ewald api --with-plugins` prints the reference with the
plugins installed here appended.
