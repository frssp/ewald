# Contributing to EWALD

Thanks for helping. Bug reports, file samples that do not open, analyses you miss and pull
requests are all welcome. For a larger change, open an issue first so we can agree on where it
belongs: many additions (file formats, modifiers, views, AI tools) fit best as a
[plugin](docs/plugins/index.md), which needs no change to EWALD itself.

## Set up

```bash
git clone https://github.com/frssp/ewald
cd ewald
pip install -e ".[dev,gui]"        # builds the C++ extension ewald._native (needs a C++17 compiler)
```

## Test

```bash
xvfb-run -a python -m pytest -q    # full suite (rendering and GUI tests need an X display with OpenGL)
python -m pytest -q --ignore=tests/test_render.py --ignore=tests/test_gui.py --ignore=tests/test_visual.py   # no display
xvfb-run -a python -m pytest tests/test_visual.py   # after touching a renderer (see docs/developer/testing.md)
mkdocs build --strict              # after touching docs/ (pip install -r docs/requirements.txt)
```

GitHub Actions currently runs only on manual dispatch, so please run the suite locally and say in
the pull request what you ran.

## Conventions

The [design decisions](docs/developer/decisions.md) say what EWALD is and is not, and why. The [developer guide](docs/developer/architecture.md) explains how the code is laid out, and
[CLAUDE.md](CLAUDE.md) is the same in short form (it is written for coding agents but is a good
checklist for people too). The rules that tests enforce:

- Never change arrays of a `DataCollection` in place; build a new array and assign it.
- Compute code is written once against `ctx.xp`, so the NumPy path also tests the CUDA path.
- Property, structure type and attribute names follow OVITO. Ported analyses are tested against
  stored OVITO/freud references, regenerated by the scripts in `tests/data/`, never by hand.
- A pull request that adds or changes a feature regenerates the feature inventory
  (`xvfb-run -a python -m ewald inventory -o docs/features.md --gui`) and updates
  [docs/todo.md](docs/todo.md); a new or changed modifier also updates `llms.txt`
  (`python -m ewald api > llms.txt`), README.md and docs/user/modifiers.md.
- Code that evaluates strings, imports by name or runs notebook cells goes through the trust
  checks in `src/ewald/trust.py` and gets a case in `tests/test_security.py`.
- Code ported from OVITO is used under its MIT option and keeps its notice
  (`tests/test_licenses.py`). Please do not copy code whose license does not allow it (VMD, for
  example).
- User-visible changes add a line under `[Unreleased]` in [CHANGELOG.md](CHANGELOG.md) and
  update the matching manual page ([docs/developer/docs.md](docs/developer/docs.md) says which).

## Windows, macOS and Linux

EWALD must behave nearly the same on all three; the maintainer runs it on Windows, while the
test machines are Linux. [docs/developer/portability.md](docs/developer/portability.md) has the
full rules; `tests/test_portability.py` checks what it can. In short: local paths only through
`os.path` or `pathlib` (never `split("/")` or `"/".join`), text files opened with
`encoding="utf-8"` (and `newline="\n"` when writing), readers that read CRLF files like LF,
name matching that ignores case, and no `fork`, `shell=True` or POSIX-only modules. Where a
change could differ on another platform, add a test that simulates it (`ntpath`,
`PureWindowsPath`, a CRLF copy of the input) and say in the pull request what you could not
check.

## Design decisions

Changes that pick between real alternatives (a new default, a file format, how the GUI is laid
out, what the AI may do) are the maintainer's call. Describe the options in an issue or in the
pull request; once a choice is made it is recorded in
[docs/developer/decisions.md](docs/developer/decisions.md) with its reason, in the pull request
that implements it. Visual changes (icons, colors, panels, figures) come with before/after
images so they can be compared.

## Pull requests

Keep one change per pull request and fill in the template. Plugins are reviewed in
[frssp/ewald-plugins](https://github.com/frssp/ewald-plugins), which holds the first-party
plugins and the plugin index.

Code, commit messages and docs are in English. Security problems go through
[SECURITY.md](SECURITY.md), not public issues. Everyone taking part follows the
[code of conduct](CODE_OF_CONDUCT.md).
